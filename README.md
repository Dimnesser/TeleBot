# Brainrot Battle — Telegram-бот

Реконструкция интерфейса и логики Telegram Mini App «Brainrot Battle» в виде
классического Telegram-бота на `aiogram`: те же экраны, тексты и переходы,
но через инлайн-клавиатуры вместо веб-интерфейса.

Проект собирается по скриншотам итеративно: каждый новый раздел добавляется
по мере того, как становится известна его логика. Готово на сейчас —
**раздел пополнения баланса («обменник»)**, **кейсы**, **апгрейдер**,
**краш** и **дайсы**.

## Готово: пополнение баланса

- **Каталог предметов** («Брейнроты» и «Гирсы»): список товаров с ценой в B,
  минимальным количеством к сдаче, поиском по названию, сортировкой по цене,
  переключаемым бафом (наценка) и корзиной с кнопками `➖ / кол-во / ➕`.
- **Заявка на депозит**: после выбора предметов бот спрашивает игровой ник,
  показывает сводку и отправляет заявку на модерацию в админ-чат с кнопками
  «Одобрить/Отклонить». Одобрение зачисляет B на баланс пользователя.
- **Очередь на депозит**: если число заявок в обработке достигает лимита
  (`MAX_CONCURRENT_TRADES`), бот показывает экран «Депозит временно
  недоступен» с оценкой времени ожидания и кнопкой «Встать в очередь».
  Когда админ закрывает заявку, освободившийся слот автоматически забирает
  самая старая заявка из очереди.
- **Telegram Stars**: ввод суммы, необязательный промокод, создание счёта
  через `send_invoice` (валюта `XTR`), автоматическое зачисление баланса по
  `successful_payment`.

Важно: это только приём пополнений (обмен предмета/Stars на внутреннюю
валюту B по фиксированному курсу с ручной модерацией).

## Готово: кейсы

**Работают на отдельной демо-валюте 🎫 (`game_tokens`), не связанной с
депозитами** — намеренное решение: кейсы это лутбокс-механика со случайным
исходом, и мы не хотим оборачивать реальные предметы/Stars из обменника в
азартную механику. Новый пользователь получает стартовый демо-баланс
(`DEMO_STARTING_TOKENS`), плюс есть кнопка «🎁 Пополнить демо-баланс» без
ограничений — это песочница для проверки механики, а не экономика.

- **Каталог**: категории «Кейсы», «Тематические», «ALL-IN», «Партнёры»,
  «Бесплатные» — все кейсы и цены/кол-во предметов из скриншотов, с
  пагинацией.
- **Карточка кейса**: цена, пул «Что может выпасть» (если подтверждён
  скриншотом), выбор количества (1/3/5), стоимость открытия.
- **Открытие**: взвешенный случайный розыгрыш (дороже — реже, вес `1/value`
  — проценты дропа нигде не показаны, это заявленное предположение),
  списание фишек, запись в инвентарь, результат в сообщении.
- **Инвентарь**: последние 10 выпавших предметов.

**Реально открываются («что может выпасть» подтверждено скриншотом)**:
«Драгон» (7 из 7 предметов) и «Тако» (6 из 11 — часть пула не видна на
скриншоте). Остальные ~30 кейсов каталога показаны с точными названиями и
ценами, но помечены 🔒 «пул не подтверждён» — открытие для них заблокировано,
чтобы не выдумывать несуществующие дропы; добавить их пул — вопрос одной
записи в `bot/data/seed_cases.py`.

## Готово: апгрейдер

Риск предметом **из инвентаря** (тем, что уже выпало из кейсов или из
прошлых апгрейдов) ради более ценного — тоже полностью в демо-контуре,
не трогает баланс B/Stars: терять можно только то, что и так было выиграно
в песочнице.

- **ТВОЙ ВКЛАД**: выбор предмета из инвентаря (`InventoryItem`).
- **ЖЕЛАЕМЫЙ ПРЕДМЕТ**: выбор цели из единого каталога «известных» предметов
  — переиспользуются подтверждённые скриншотами названия/цены из обменника
  (`DepositItem`) и кейсов (`CaseItem`), только те, что дороже вклада.
- **Пресеты x2/x5/x10/30%/50%/75%**: автоматически подбирают ближайший по
  цене известный предмет под нужный множитель/шанс.
- **ШАНС**: считается как `вклад / цель × 100%`, обрезан до 1–95% (см. ниже).
  Показывается текстовым индикатором-полоской вместо кругового диска со
  скриншота (Telegram-бот не рисует произвольную графику).
- **ПРОКАЧАТЬ**: списывает вложенный предмет из инвентаря; при успехе в
  инвентарь добавляется желаемый предмет, при неудаче — просто теряется.

## Готово: краш

Ставка — тоже предмет из инвентаря («ВЫБЕРИ БРЕЙНРОТА»). В отличие от
оригинала (общий раунд с живой анимацией на всех игроков сразу в Mini App)
здесь **раунд личный**: Telegram-бот технически не может транслировать один
и тот же полёт ракеты синхронно всем участникам, поэтому у каждого игрока
свой независимый раунд.

- **🚀 СТАРТ**: списывает ставку и запускает фоновую задачу, которая раз в
  `CRASH_TICK_SECONDS` дорисовывает растущий множитель в то же сообщение.
- **🛑 ЗАБРАТЬ**: останавливает задачу и начисляет `ставка × текущий множитель`
  новым предметом в инвентарь.
- Если не забрать до точки обрыва (или истёк `CRASH_MAX_DURATION_SECONDS`) —
  раунд сам завершается крахом, ставка просто теряется (она уже была списана
  при старте).
- Точка обрыва — хвостатое распределение `house_edge / random()`, рост
  множителя — экспонента от времени; обе формулы нигде не подписаны числом
  на скриншоте, см. «Не подтверждено скриншотами» ниже.
- Раунд хранится только в памяти процесса — не переживает перезапуск бота
  (демо-контур, персистентность «зависших» раундов не реализована).

## Готово: дайсы

Тоже ставка предметом из инвентаря. Бросок 4 кубиков, шести цветов на
выбор, таблица выплат — один в один со скриншота «Правила игры»:
`0/4 → проигрыш, 1/4 → x2, 2/4 → проигрыш, 3/4 → проигрыш, 4/4 → x3`, плюс
отдельное редкое событие «БОНУС 🌈 → x10» поверх таблицы.

## Не подтверждено скриншотами (сделано по разумному минимуму)

- Наценки «бафов» — список и проценты не видны на скриншотах, использован
  плейсхолдер-набор в `bot/data/buffs.py`.
- Формула оценки времени ожидания в очереди — на скриншоте только пример
  значения, использована простая модель в `bot/services/deposit_service.py`.
- Курс Stars → B по умолчанию 1:1 (`STARS_TO_BALANCE_RATE`).
- Иконки предметов — эмодзи-приближения; в оригинале кастомная пиксель-арт
  графика.
- Веса выпадения предметов из кейсов (`1/value`) — проценты не показаны ни
  на одном скриншоте, см. `bot/services/cases_service.py`.
- Пункт «КЕЙСЫ» в главном меню — в исходном хамбургер-меню его нет (кейсы,
  видимо, часть главной страницы), поэтому добавлен отдельным явным пунктом,
  а не встроен в «ГЛАВНАЯ», чтобы не гадать.
- Формула шанса апгрейдера (`вклад / цель`, обрезка 1–95%) — на скриншоте
  виден только диск с подписью «ШАНС» без числа, формула — то единственное,
  что делает кнопки-множители и кнопки-проценты взаимно согласованными,
  см. `bot/services/upgrader_service.py`.
- Формула роста множителя и распределение точки обрыва в краше — на
  скриншоте видно только текущее число и историю прошлых раундов, без
  формул; см. `bot/services/crash_service.py`.
- «Общий раунд» краша реализован как личный на каждого игрока — Telegram-бот
  не может синхронно анимировать одну и ту же ракету всем сразу.
- Условие срабатывания «БОНУС» в дайсах — на скриншоте отдельная строка без
  своей «N/4», поэтому реализовано как независимый шанс поверх таблицы
  совпадений (`DICE_BONUS_CHANCE_PERCENT`), см. `bot/services/dice_service.py`.

## Структура проекта

```
bot/
  app.py                 сборка и запуск aiogram-приложения
  config.py               конфигурация из окружения
  handlers/
    start.py              /start, регистрация пользователя
    menu.py                навигация по главному меню
    deposit/
      catalog.py           каталог предметов, корзина, заявка, очередь
      stars.py              пополнение через Telegram Stars
      admin.py               модерация заявок, продвижение очереди
    cases/
      catalog.py             каталог кейсов, открытие, инвентарь, демо-баланс
    upgrader.py              риск предметом из инвентаря ради более ценного
    crash.py                 растущий множитель, кэшаут до обрыва
    dice.py                  бросок 4 кубиков против выбранного цвета
  keyboards/               инлайн-клавиатуры и callback_data-фабрики
  states/                  FSM-состояния (aiogram)
  services/
    crash_runtime.py         фоновые asyncio-задачи активных раундов краша
    ...                      + корзина, наценки, очередь, кейсы, апгрейдер, краш, дайсы, уведомления
  database/
    models.py               модели SQLAlchemy
    engine.py                 инициализация БД, сид каталога/кейсов
    repo/                      операции с БД (users, deposit_*, cases, inventory, known_items)
  data/                     сид-данные каталога, бафов и кейсов
  utils/texts.py            все тексты сообщений бота
main.py                    точка входа
tests/                      тесты (чистая логика + БД на in-memory SQLite)
```

## Быстрый старт

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впишите BOT_TOKEN (от @BotFather), при необходимости ADMIN_IDS и ADMIN_CHAT_ID

python main.py
```

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота, обязателен |
| `ADMIN_IDS` | — | Telegram ID администраторов через запятую |
| `ADMIN_CHAT_ID` | — | Чат для уведомлений о новых заявках на депозит |
| `DATABASE_URL` | `sqlite+aiosqlite:///./data/brainrot_battle.db` | Строка подключения SQLAlchemy |
| `STARS_TO_BALANCE_RATE` | `1` | Сколько B начисляется за 1 Telegram Star |
| `MIN_STARS_AMOUNT` / `MAX_STARS_AMOUNT` | `50` / `100000` | Диапазон суммы пополнения через Stars |
| `MAX_CONCURRENT_TRADES` | `5` | Сколько заявок на трейд обрабатывается одновременно |
| `AVG_TRADE_MINUTES` | `8` | Среднее время трейда для оценки очереди |
| `UPGRADER_MIN_CHANCE_PERCENT` / `UPGRADER_MAX_CHANCE_PERCENT` | `1` / `95` | Границы шанса успеха в апгрейдере |
| `DEMO_STARTING_TOKENS` | `2000` | Стартовый демо-баланс 🎫 для кейсов при регистрации |
| `DEMO_TOPUP_TOKENS` | `1000` | Сколько 🎫 начисляет кнопка «Пополнить демо-баланс» |
| `CRASH_TICK_SECONDS` | `1.2` | Интервал анимации множителя в краше (сек) |
| `CRASH_GROWTH_RATE` | `0.07` | Скорость роста множителя за тик |
| `CRASH_MAX_DURATION_SECONDS` | `30` | Safety-cap: раунд краша принудительно завершается через столько секунд |
| `CRASH_HOUSE_EDGE` | `0.97` | Параметр распределения точки обрыва (`house_edge / random()`) |
| `CRASH_MAX_MULTIPLIER` | `100` | Потолок множителя в краше |
| `DICE_BONUS_CHANCE_PERCENT` | `3` | Шанс редкого события «БОНУС» в дайсах |
| `DICE_BONUS_MULTIPLIER` | `10` | Множитель выигрыша при «БОНУС» |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты используют in-memory SQLite и не ходят в сеть.

```bash
docker build -t brainrot-battle .
docker run -d --name brainrot-battle --env-file .env -v "$PWD/data:/app/data" --restart unless-stopped brainrot-battle
```
