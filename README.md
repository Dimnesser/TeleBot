# TeleBot — умный AI-ассистент в Telegram

Телеграм-бот на Claude, который отвечает на вопросы по любым темам: учёба,
программирование, наука, игры, тексты, бытовые задачи. Помнит контекст диалога,
понимает картинки, при необходимости ищет в интернете.

## Возможности

- **Ответы по любым темам** с системным промптом, который требует точности и
  честного «не знаю» вместо выдумок.
- **Память диалога** по каждому чату с обрезкой по количеству сообщений и объёму
  символов; по желанию сохраняется на диск и переживает перезапуск.
- **Веб-поиск** через серверный инструмент Anthropic: под ответом появляются
  ссылки на источники, которые реально вернул поиск.
- **Картинки и скриншоты**: фото и файлы-изображения уходят в модель как vision-вход.
- **Текстовые файлы**: `.txt`, `.md`, код и подобное разбираются как текст.
- **Постепенный вывод**: сообщение появляется сразу и дописывается по мере генерации.
- **Markdown → Telegram HTML**: жирный, курсив, ссылки, списки и блоки кода с
  подсветкой языка. Длинные ответы автоматически режутся по 4096 символов так,
  чтобы блоки кода не ломались.
- **Работа в группах**: бот отвечает только на упоминание или ответ на своё сообщение.
- **Ограничение доступа** списком Telegram ID, если бот приватный.

## Быстрый старт

```bash
git clone https://github.com/Dimnesser/TeleBot.git
cd TeleBot

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впишите TELEGRAM_BOT_TOKEN и ANTHROPIC_API_KEY

python main.py
```

Токен бота выдаёт [@BotFather](https://t.me/BotFather), ключ API — консоль Anthropic.

## Настройки

Всё читается из переменных окружения или файла `.env` (переменные окружения
имеют приоритет).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | Токен бота, обязателен |
| `ANTHROPIC_API_KEY` | — | Ключ API; можно опустить, если настроен `ant auth login` |
| `CLAUDE_MODEL` | `claude-opus-5` | Модель |
| `CLAUDE_EFFORT` | `medium` | Глубина рассуждений: `low`…`max`, пусто — по умолчанию модели |
| `CLAUDE_MAX_TOKENS` | `8000` | Лимит длины ответа |
| `CLAUDE_TIMEOUT_SECONDS` | `180` | Таймаут запроса |
| `ENABLE_WEB_SEARCH` | `true` | Веб-поиск |
| `WEB_SEARCH_MAX_USES` | `5` | Максимум поисков на один ответ |
| `ENABLE_REFUSAL_FALLBACK` | `true` | Серверный фолбэк при отказе модели |
| `HISTORY_TURNS` | `20` | Сколько сообщений помнить |
| `HISTORY_MAX_CHARS` | `40000` | Бюджет контекста в символах |
| `HISTORY_FILE` | — | Путь к файлу истории; пусто — память только в процессе |
| `ALLOWED_USER_IDS` | — | Белый список ID через запятую; пусто — доступ всем |
| `MAX_IMAGE_BYTES` | `5242880` | Максимальный размер картинки |
| `MAX_DOCUMENT_BYTES` | `204800` | Максимальный размер текстового файла |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

Глубина рассуждений влияет на качество и на стоимость. `low` подойдёт для
болтовни и простых вопросов, `high` и выше — для сложных задач и кода.
Для моделей, которые не принимают `effort` (например, Haiku), параметр
отбрасывается автоматически.

## Структура проекта

```
bot/
  app.py              сборка и запуск приложения Telegram
  claude.py           обращение к Messages API: стриминг, веб-поиск, ошибки
  config.py           конфигурация из окружения
  handlers.py         команды и обработчики сообщений
  history.py          память диалогов с обрезкой и сохранением на диск
  prompts.py          системный промпт и тексты бота
  reply.py            отправка ответа и индикатор набора
  telegram_format.py  Markdown → HTML Telegram, разбиение длинных сообщений
main.py               точка входа
tests/                тесты
```

```bash
docker build -t telebot .

```

## Запуск как systemd-сервис

```ini
[Unit]
Description=Telegram AI assistant
After=network-online.target

[Service]
WorkingDirectory=/opt/TeleBot
EnvironmentFile=/opt/TeleBot/.env
ExecStart=/opt/TeleBot/.venv/bin/python main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## Как это работает

1. Сообщение попадает в обработчик, который проверяет доступ и — в группах —
   адресовано ли оно боту.
2. К истории чата добавляется новая реплика, собирается запрос к Messages API:
   системный промпт отдельным кэшируемым блоком, дальше диалог.
3. Ответ читается потоком: бот сразу создаёт сообщение «Думаю…» и дописывает его.
4. Если модель взяла паузу на веб-поиск (`pause_turn`), бот продолжает тот же ход,
   пока ответ не будет готов.
5. Готовый текст переводится в HTML, режется на сообщения и отправляется,
   после чего сохраняется в историю.

Отказ модели (`refusal`) в историю не попадает, чтобы он не тянул за собой
следующие ответы.
